# FixLedger UI 设计

## 1. 设计目标

FixLedger 是一个面向家庭用户的设备保修与耗材管理工具。UI 既要有后台管理系统的清晰结构，也要避免过于企业化和冰冷，要让用户感觉这是一个“家庭设备档案本”。

设计目标：

- 信息清晰：设备、保修、耗材、维修、提醒一眼可见。
- 生活化：文案和交互贴近日常家庭场景。
- 高效率：常用操作路径短，例如新增设备、上传发票、记录维修。
- 可演示：首页看板、设备详情、提醒日历、AI 建议页面适合面试展示。
- 可扩展：后续能支持移动端、小程序或二维码标签。

## 2. 视觉方向

### 2.1 风格关键词

- 温暖。
- 清晰。
- 轻量。
- 有秩序。
- 生活工具感。

### 2.2 色彩建议

不使用过重的企业蓝，也不走 AI 常见紫色风格。

建议主色：

```text
主色：#2F7D68  家庭绿 / 可靠感
辅助色：#F2A65A  温暖橙 / 提醒
背景色：#F7F3EA  米色 / 生活感
文本色：#24312F  深绿黑
危险色：#D9534F  维修 / 过期 / 警告
成功色：#4E9F3D  正常 / 已完成
```

Element Plus 可通过 CSS 变量定制主色。

### 2.3 布局风格

- 桌面端采用侧边栏 + 顶部栏 + 内容区。
- 内容区多使用卡片、时间线、列表、统计块。
- 设备详情页采用聚合式布局。
- 移动端后续可做单列卡片布局。

## 6. 关键交互

### 6.1 AI 结果确认

AI 生成的结构化信息不能直接落库覆盖用户数据。

交互要求：

- AI 结果展示为可编辑表单。
- 用户点击确认后再保存。
- 保存前提示“AI 结果仅供参考”。

### 6.2 删除确认

删除设备、保修、耗材、维修、附件时必须二次确认。

设备删除文案：

```text
删除后该设备将不再显示，但历史记录会保留用于统计和追溯。确认删除吗？
```

### 6.3 状态流转

维修状态修改使用弹窗，不允许表格内直接无确认修改。

弹窗内容：

- 目标状态。
- 处理说明。
- 维修费用。
- 完成时间。

### 6.4 文件上传

文件上传要求：

- 展示允许类型。
- 展示文件大小限制。
- 上传中进度条。
- 上传失败错误提示。

## 8. 表单校验

### 8.1 设备表单

- 设备名称必填，最多 128 字。
- 购买价格不能小于 0。
- 购买日期不能晚于今天。
- 序列号最多 128 字。

### 8.2 保修表单

- 开始日期必填。
- 结束日期必填。
- 结束日期不能早于开始日期。
- 提前提醒天数不能小于 0。

### 8.3 耗材表单

- 耗材名称必填。
- 更换周期必须大于 0。
- 上次更换日期不能晚于今天。
- 提前提醒天数不能小于 0。

### 8.4 维修表单

- 标题必填。
- 故障描述必填。
- 维修费用不能小于 0。
- 完成时间不能早于故障发生时间。

## 9. 空状态设计

### 9.1 没有设备

文案：

```text
还没有设备档案。先添加一台家里的设备吧，比如净水器、路由器或耳机。
```

按钮：

```text
新增设备
```

### 9.2 没有提醒

文案：

```text
目前没有待处理提醒，家庭设备状态良好。
```

### 9.3 没有维修记录

文案：

```text
这台设备还没有维修记录，希望它一直好用。
```

## 10. 响应式设计

第一版优先桌面端，但布局要预留移动端适配空间。

桌面端：

- 侧边栏固定。
- 内容区最大宽度自适应。
- 表格展示完整字段。

移动端：

- 侧边栏折叠为抽屉。
- 表格切换为卡片列表。
- 设备详情 Tabs 横向滚动。
- 首页统计卡片两列或单列展示。
