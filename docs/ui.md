# FixLedger UI 设计

## 1. 设计目标

FixLedger 是一个面向家庭用户的设备保修与耗材管理工具。UI 要从“后台管理系统”转向“家庭设备管家”。第一版可以保留清晰结构，但 P8 之后默认入口必须围绕家庭场景、时间、房间和设备生命周期组织，而不是围绕数据库模块组织。

设计目标：

- 场景优先：用户先看到“我的家、本周事项、家庭日历、房间设备”，而不是一组管理模块。
- 信息清晰：设备、保修、耗材、维修、提醒一眼可见。
- 高效率：常用操作路径短，例如添加设备、上传凭证、记录维修、确认耗材已更换。
- 可演示：我的家、家庭日历、设备档案、凭证盒和辅助工具适合面试展示。
- 可扩展：后续能支持移动端、小程序或二维码标签。


## 1.1 UI 规范边界

UI 设计必须服从 `docs/spec.md` 和 `docs/decisions/0004-household-scene-first-ui.md`：FixLedger 的第一印象应是家庭设备管家，而不是普通管理平台。

执行约束：

- 页面优先按家庭场景、时间、房间、设备生命周期组织，而不是按数据库表组织。
- 表格可以作为高级视图，但首页和详情页优先使用日历、卡片、时间线、凭证盒等生活化表达。
- AI 页面只表达“辅助录入、辅助分析、辅助总结”，不能让产品变成 AI 主题工具。
- 新增页面或交互先更新本文件，再实现前端代码。
- 前端验证至少执行 `npm run build`；视觉变更需要补充人工冒烟或截图说明。
## 2. 视觉方向

### 2.1 风格关键词

- 简洁。
- 清晰。
- 实用。
- 通透。
- 新潮。
- 家庭设备液态玻璃工作台感。

### 2.2 色彩建议

不使用旧绿色作为品牌主色，不走 AI 常见的深紫霓虹风格，也不再使用大面积暖橙、米色渐变或土味宣传页视觉。
当前视觉采用浅色产品工具风：银白玻璃底、克制橙色主操作、低饱和青蓝/中性色作为轻量辅助，强调通透、轻盈、可读和实用信息密度。

建议主色：

```text
主色：#0A84FF  系统蓝 / 主操作与当前态
强调色：#8E8CFF  淡紫 / 轻量高亮与辅助 tint
辅助色：#64D2FF  浅青 / 图表与提示点
背景色：#F3F8FF  银蓝浅底 / 页面环境
玻璃层：rgba(255,255,255,0.56-0.90) + backdrop-filter / 面板、导航、控件
文本色：#17181C  高对比正文
弱文本：#667085  辅助信息
危险色：#FF3B30  过期 / 删除 / 高风险提醒
警告色：#C77D10  临期 / 需要关注
```

Element Plus 可通过 CSS 变量定制主色。

### 2.3 布局风格

- 桌面端采用简洁侧边栏 + 顶部家庭状态栏 + 内容区。
- 内容区优先展示待办、筛选、列表、日历和凭证完整度，避免大 Hero、大字号和装饰性卡片。
- 页面背景使用浅银蓝和淡紫环境色，玻璃材质主要用于导航、面板、工具栏和表单控件。
- 卡片使用半透明玻璃层、细高光边框、轻阴影和清晰状态；按钮可使用系统蓝到淡紫的轻量渐变。
- 日历提醒使用状态点表达，不使用拟物图钉。
- 设备详情页采用聚合式布局。
- 移动端后续可做单列卡片布局。

## 3. 信息架构

P8 之后的信息架构从“模块驱动”调整为“家庭场景驱动”。保修、耗材、维修不再全部作为一级入口，而是沉淀到家庭日历、设备档案和凭证盒里。

```text
登录 / 注册
  ↓
主应用布局
  ├── 我的家
  │   ├── 家庭健康分
  │   ├── 本周设备事项
  │   ├── 家庭提醒日历
  │   └── 房间设备概览
  ├── 家庭日历
  │   ├── 保修到期
  │   ├── 耗材更换
  │   └── 维修记录关联（维修跟进提醒后续增强）
  ├── 设备档案
  │   ├── 房间设备卡片墙
  │   ├── 设备详情
  │   └── 生命周期时间线
  ├── 凭证盒
  │   ├── 发票
  │   ├── 保修卡
  │   ├── 说明书
  │   └── 维修单
  ├── 辅助工具
  └── 我的家庭
```

保留以下页面作为高级入口或详情入口，但导航文案不直接暴露“管理平台”语气：

- 保修记录：从家庭日历、设备档案或凭证盒进入。
- 耗材记录：从家庭日历、设备档案或更换计划进入。
- 维修记录：从家庭日历、设备档案或维修足迹进入。
- 提醒中心：弱化为待办事项，不作为核心产品主线。

## 5. 页面设计

## 5.1 登录页

目标：快速登录系统，用少量文案说明项目定位，避免做成宣传页。

布局：

- 单列居中登录卡片，优先展示账号、密码和登录操作。
- 顶部保留小品牌和一句家庭设备档案说明，不使用大标题海报区。
- 演示账号以轻量提示条呈现，用户点击后才填入。

字段：

- 账号。
- 密码。
- 记住我（二期）。

操作：

- 登录。
- 跳转注册。

状态：

- 表单校验。
- 登录中 loading。
- 登录失败提示。

## 5.2 注册页

字段：

- 用户名。
- 邮箱。
- 昵称。
- 密码。
- 确认密码。

注册成功后：

- 自动创建默认家庭空间。
- 跳转首页。

## 5.3 主布局

### 侧边栏

侧边栏要像家庭应用导航，而不是后台模块菜单。一级入口控制在 5 个以内：

- 我的家：家庭状态总览、健康分、本周事项、家庭日历和房间概览。
- 家庭日历：按月份查看保修、耗材和维修提醒。
- 设备档案：按房间查看设备卡片，进入单台设备生命周期。
- 凭证盒：集中保存发票、保修卡、说明书和维修单。
- 辅助工具：票据提取、故障建议和维修总结。

辅助入口：

- 我的家庭：家庭空间和成员设置。
- 高级记录：保修、耗材、维修、提醒等表格视图可以保留，但弱化为二级或快捷入口。

### 顶部栏

内容：

- 当前家庭空间切换。
- 家庭一句话状态，例如“本周有 3 件设备小事”。
- 用户头像。

家庭上下文恢复规则：

- 前端可以缓存最近一次使用的家庭空间 ID，方便刷新后继续操作。
- 每次登录态恢复或刷新家庭列表后，都必须确认缓存 ID 仍存在于当前用户可访问家庭列表。
- 如果缓存 ID 已失效，自动切换到第一个可访问家庭；如果列表为空，则清空当前家庭并等待用户创建家庭空间。

## 6. 关键交互

### 6.1 AI 结果确认

AI 生成的结构化信息不能直接落库覆盖用户数据。

交互要求：

- AI 结果展示为可编辑表单。
- 用户点击确认后再保存。
- 保存前提示“AI 结果仅供参考”。

### 6.2 删除确认

删除设备、保修、耗材、维修、附件时必须二次确认。

设备删除文案：

```text
删除后该设备将不再显示，但历史记录会保留用于统计和追溯。确认删除吗？
```

### 6.3 状态流转

维修状态修改使用弹窗，不允许表格内直接无确认修改。

弹窗内容：

- 目标状态。
- 处理说明。
- 维修费用。
- 完成时间。

### 6.4 文件上传

文件上传要求：

- 展示允许类型。
- 展示文件大小限制。
- 上传中进度条。
- 上传失败错误提示。

## 8. 表单校验

### 8.1 设备表单

- 设备名称必填，最多 128 字。
- 购买价格不能小于 0。
- 购买日期不能晚于今天。
- 序列号最多 128 字。

### 8.2 保修表单

- 开始日期必填。
- 结束日期必填。
- 结束日期不能早于开始日期。
- 提前提醒天数不能小于 0。

### 8.3 耗材表单

- 耗材名称必填。
- 更换周期必须大于 0。
- 上次更换日期不能晚于今天。
- 提前提醒天数不能小于 0。

### 8.4 维修表单

- 标题必填。
- 故障描述必填。
- 维修费用不能小于 0。
- 完成时间不能早于故障发生时间。

## 9. 空状态设计

### 9.1 没有设备

文案：

```text
还没有设备档案。先添加一台家里的设备吧，比如净水器、路由器或耳机。
```

按钮：

```text
新增设备
```

总览和凭证盒要求：

- 我的家总览在设备数为 0 时显示首个设备引导面板，解释设备档案会串起保修、耗材、维修和凭证。
- 凭证盒在没有可选设备时不展示上传主流程，优先提示先创建设备档案。
- 空状态按钮必须直接进入 `/devices/create`，避免用户在多个空页面之间来回跳转。

### 9.2 没有提醒

文案：

```text
目前没有待处理提醒，家庭设备状态良好。
```

### 9.3 没有维修记录

## 14. P9.6 设备护照入口体验调整

P9.6 继续解决“项目看起来像普通管理平台”的问题，重点调整 `/devices` 设备护照入口和登录页演示体验。

### 14.1 设备护照卡片墙

调整原因：

- 家庭用户通常先按房间或使用场景理解设备，例如厨房、客厅、书房，而不是先看一张资产表。
- 设备列表如果默认就是表格，容易显得像通用后台管理系统。
- 设备护照应该像“家庭设备卡片墙”，让面试演示时能直观看到产品定位。

调整后 `/devices` 默认结构：

```text
页面头部：设备护照标题 + 家庭设备状态摘要 + 新增设备
筛选区：关键词、分类、状态
房间卡片墙：按 location 分组展示设备卡片
设备卡片：名称、品牌型号、分类、状态、购买日期、下次提醒、快捷操作
高级清单：折叠展示表格视图，保留批量浏览和精确管理能力
分页区：保留后端分页，不一次性拉取全部设备
```

交互要求：

- 卡片点击“打开护照”进入设备详情。
- 卡片内保留编辑、改状态和删除入口。
- 房间分组为空时使用“未设置房间”。
- 移动端下房间卡片墙变为单列，操作按钮自动换行。

### 14.2 演示登录体验

调整原因：

- 登录页默认填入演示密码，容易让面试官误解为真实密钥硬编码或安全意识不足。
- 更合理的方式是空表单 + 明确“填入演示账号”按钮，让演示账号是刻意的演示能力。

调整后：

- 账号和密码默认留空。
- 提供“填入演示账号”按钮，一键填入 `demo / fixledger123`。
- 页面文案说明演示账号用于本地体验，不代表真实生产密钥。


## 15. P15 米家风格视觉升级

P15.1 采用“参考米家 App，但不复制品牌资产”的方向：以家庭设备为中心，使用暖白背景、轻量卡片、柔和阴影、克制的橙色强调和清晰设备状态，让 FixLedger 更像家庭设备管家，而不是传统后台。

### 15.1 视觉原则

- 背景：暖白到浅灰的生活化背景，避免大面积深色和强烈渐变。
- 卡片：设备卡、提醒卡、健康分卡使用大圆角和轻阴影，模拟家庭设备卡片。
- 色彩：主色从偏绿调整为米家感的暖橙/暖黄，辅以墨色文字和低饱和绿色表示健康状态。
- 信息层级：首页先看“家里设备状态”，设备页先看“设备卡片墙”，表格收进高级清单。
- 动效：只保留轻微 hover、页面卡片浮起和按钮反馈，不做炫技动画。
- 响应式：移动端按 App 思路单列展示，侧边栏转为顶部/纵向导航。

### 15.2 首批改造页面

| 页面 | 改造目标 |
| --- | --- |
| 登录页 | 更像家庭设备 App 欢迎页，突出设备护照、家庭日历、凭证盒、AI 辅助四个能力卡片 |
| 主布局 | 侧边栏改为轻量家庭控制台，当前家庭卡片和 AI 提示更克制 |
| 我的家 | Hero、健康分、指标卡、房间概览和家庭日历统一为米家式卡片 |
| 设备护照 | 房间分组和设备卡片更像设备面板，状态、提醒、保修信息更醒目 |
| 设备详情 | 从普通详情表升级为设备护照封面 + 生命周期统计 + 时间线 |

### 15.3 边界说明

- 本次只做视觉与信息层级升级，不新增智能家居控制、设备联动或 IoT 控制能力。
- 不使用米家 Logo、图标或品牌素材，只参考其浅色、设备卡片和家庭空间组织方式。
- AI 继续作为辅助录入和总结能力，不变成页面主角。


### 15.4 公开产品首页

用户要求增加一个类似米家官网的首页。后续体验反馈认为原先的大 Hero 和宣传内容过重，因此该页面调整为 FixLedger 的轻量公开入口和登录引导，而不是完整官网或登录后的“我的家”工作台。

页面结构：

```text
顶部：小品牌、登录、注册
主体：居中入口卡片，包含简短项目说明和登录/注册操作
信息条：保修提醒、耗材周期、凭证归档三项能力
底部：本地演示账号提示
```

设计边界：

- 参考米家官网的浅色、留白和克制质感，不使用米家 Logo、图片或商品素材。
- 不再使用大 Hero、大字号营销文案、复杂功能卡片矩阵或底部宣传 CTA。
- 首页不做商城导购，不展示智能硬件售卖，也不承诺设备联动控制。
- 首页 CTA 指向登录页，真实业务仍在登录后的家庭空间内完成。

### 15.5 凭证盒深化

P15.2 将 `/files` 从“按业务 ID 查询附件”的后台工具页，升级为家庭设备凭证盒。页面仍复用后端现有附件接口，不新增数据库结构；体验上先让用户以设备为中心选择凭证类型，再完成上传、查看、预览和下载。

页面结构：

```text
页面头部：凭证盒标题 + 上传入口 + 后端鉴权说明
设备选择：选择需要整理凭证的家庭设备
完整度卡片：按发票、说明书、保修、维修、耗材显示已归档/待补充
凭证类型：发票、说明书、保修、维修、耗材分段切换
附件区：文件名、大小、类型、下载、预览、删除
预览抽屉：图片直接展示，PDF 使用浏览器内嵌预览，不支持类型提示下载
```

P16.1 后，凭证盒读取链路升级为后端聚合接口：

```text
设备列表：用于选择家庭设备
凭证盒聚合：GET /api/families/{familyId}/devices/{deviceId}/credential-box
说明书搜索：GET /api/families/{familyId}/devices/{deviceId}/manuals/search?keyword=reset
上传/预览/下载/删除：继续复用 /api/families/{familyId}/files 系列接口
```

设计边界：

- 凭证盒不直接暴露 RustFS/MinIO 对象地址，预览和下载都走后端鉴权下载接口。
- 完整度由后端按 `DEVICE`、`MANUAL`、`WARRANTY`、`MAINTENANCE`、`CONSUMABLE` 五类统一计算。
- 保修、维修和耗材可挂载对象由后端按设备聚合返回，前端不再维护业务对象名称映射。
- P16.2 第一版说明书搜索只展示文件名和短片段，预览/下载仍复用后端鉴权附件接口。
- 扫描件 OCR、复杂 PDF 解析、对象存储临时 URL、凭证自动分类仍是后续增强，不阻塞当前凭证盒闭环。

## 16. 用户反馈后的全前端视觉重做

本轮根据体验反馈废弃上一版“暖橙大卡片/官网 Hero/宣传式大字”的视觉方向，改为更简洁、克制、实用的家庭设备工作台。随后根据用户继续反馈，当前视觉从“简洁绿色工具风”和“蓝紫 Liquid Glass”继续收敛为浅色产品工具风：银白玻璃、克制橙色主操作、浅灰白面板和轻量层级。P17.5 对公开首页单独参考 `home.mi.com` 的浅色留白、顶部导航和产品预览节奏，但只吸收官网式清爽结构，不复制米家品牌、不展示商城导购，也不回到旧的大字海报。

### 16.1 设计调整

- 首页和登录页不再使用压迫性大 Hero、大标题、宣传型卡片矩阵和暖色渐变；公开首页允许使用克制的产品官网首屏，登录页仍保持轻量入口、清晰表单和演示账号说明。
- 主布局保留侧边导航，但菜单文案收敛为“总览、日历、设备、凭证、辅助、家庭设置”，降低后台管理感。
- 首页看板优先展示待办、设备状态、房间概览和提醒日历；提醒使用状态点，不使用拟物图钉。
- 设备页文案从“设备护照”收敛为“设备档案”，保留按房间分组和高级清单。
- 凭证盒改为设备维度的凭证完整度、类型切换、说明书搜索和附件清单，不再使用大面积暖橙卡片或硬白块。
- 辅助工具页弱化 AI 主角感，只表达“辅助录入、辅助分析、辅助总结”。

### 16.2 视觉约束

- 禁止新增旧绿色主色、大面积暖橙、米色渐变、土味宣传页式大 Hero、大字号营销文案和装饰性图形。
- 公开首页可以参考 `home.mi.com` 的浅色留白、导航节奏、产品界面预览和少量橙色 CTA，但不能使用米家 Logo、商品图、商城导购、智能硬件控制承诺或大面积暖橙海报。
- 允许克制使用 Liquid Glass，但玻璃层必须服务于导航、面板、工具栏、表单和卡片层级，不允许为了装饰堆叠透明材质。
- Liquid Glass 当前以 `surface / elevated / chip / tint` 四类材质表达：页面级面板更通透，控件级元素更清晰，选中态使用克制橙色和低饱和信息色。
- 参考纯 CSS Liquid Glass 文档时，只吸收半透明底、`backdrop-filter`、细高光边框、内阴影和 `::after` 液体反光；不照搬黑色重投影、低对比白字、emoji 图标或外部背景图依赖。
- 玻璃面板的伪元素必须设置 `pointer-events: none`，并通过 `isolation`、明确的 `z-index` 和内容层级避免遮挡输入、按钮和表格。
- 页面字号保持克制，只有页面标题和关键数字可适度放大。
- 卡片默认使用 `var(--fl-glass)`、`var(--fl-glass-chip)`、`var(--fl-glass-line)`、`var(--fl-radius-md/lg)`、`backdrop-filter` 和低阴影。
- 正文和表格必须保持足够对比度，透明层不应影响信息阅读。
- 按钮、输入框和主要可点元素应保持 44px 左右的可触达高度，并提供 hover、focus、pressed 三类状态。
- 动效只用于轻量反馈，不使用大范围滚动视差、连续漂浮或强动态背景；必须继续尊重 `prefers-reduced-motion`。
- 状态色只用于风险、临期、成功等语义，不作为装饰主色。
- 视觉调整不得改变 FixLedger 的家庭设备生命周期管理定位。

### 16.3 P17.5 公开首页规范

P17.5 的公开首页是给访客和面试演示使用的第一屏，不承载登录后的家庭工作台职责。

页面结构：

```text
顶部导航：FixLedger 品牌、设备档案、提醒日历、凭证盒、登录、进入演示
首屏主体：左侧短文案 + 两个 CTA，右侧 FixLedger 产品界面预览
能力露出：设备档案、提醒日历、凭证盒三项核心能力
演示说明：展示 demo / fixledger123，但不自动填入密码
```

设计要求：

- H1 使用一句短标题，桌面端上限控制在中等展示字号，移动端不超过两到三行。
- 副文案只解释家庭设备生命周期管理，不做泛资产管理、商城或 AI 平台叙事。
- 橙色只用于品牌点、主 CTA 和少量状态强调；页面主底色仍是浅灰白和通透玻璃。
- 右侧产品预览要像真实工作界面：设备数量、待处理事项、保修/耗材/维修/凭证状态一眼可见。
- 移动端隐藏次级导航，CTA 自动换行，产品预览和能力卡片变为单列。

### 16.4 P17.6 登录注册入口规范

登录和注册页是公开首页之后的第一段真实操作，视觉上必须和 `/` 保持同源，而不是另起一套蓝紫玻璃系统。

设计要求：

- 背景延续浅灰白、细边框、低阴影和少量橙色品牌点，不使用大面积蓝紫 tint。
- 登录页优先展示账号、密码、登录按钮和演示账号填入；说明文字保持简短。
- 注册页保持单列表单，不添加营销卡片或复杂步骤。
- 主按钮使用同公开首页一致的橙色强调，次级操作使用白色/浅灰玻璃按钮。
- 品牌入口点击返回 `/`，但登录/注册页本身不承担官网介绍职责。
- 移动端表单宽度贴合屏幕留白，按钮不溢出，输入框高度保持约 44px。

### 16.5 P17.7 全前端收口规范

P17.7 将公开入口、认证页和登录后主应用统一为一套浅色产品工具风。该阶段不新增业务模块，只治理视觉割裂、旧文案和主题 token。

设计要求：

- 全局主操作色统一为克制橙色，低饱和青蓝和中性色只允许作为图表辅助色或信息色，不再出现蓝紫主品牌感。
- 主布局、看板、设备、凭证、辅助工具和设置页使用同一套浅灰白背景、细边框、低阴影和清晰表单控件。
- 当前页面命名统一使用“设备档案”，历史阶段中的“设备护照”只保留在开发记录里。
- 登录后页面优先表达实用信息密度：待办、筛选、表格、列表、日历和凭证完整度，避免营销式大标题。
- 页面可以保留轻量 `backdrop-filter`，但不得出现大面积蓝紫玻璃、强发光、装饰性光团或多主题拼接。
- 公开首页首屏必须在桌面和移动端底部露出下一段能力内容；移动端产品预览应压缩为关键信息，避免长列表把首页变成满屏海报。

### 16.6 P18 空数据与加载态规则

P18 的空数据引导只用于真实的新用户状态，不用于加载中或筛选无结果状态。

设计要求：

- 总览页必须等首页统计加载完成后，再根据设备总数判断是否展示“添加第一台设备”。
- 凭证盒必须等设备列表加载完成后，再判断家庭是否没有任何设备。
- 凭证盒存在设备搜索关键字时，列表为空应展示“没有匹配设备”的搜索空状态，并提供清空搜索操作。
- 只有未搜索且确认当前家庭设备数为 0 时，凭证盒才展示首设备引导，并隐藏上传入口、凭证类型切换和归档主流程。
- 无家庭上下文或家庭切换过程中，不展示上一家庭的设备选项、凭证完整度和附件列表。

### 16.7 P19-P23 演示与协作体验规则

P19-P23 在不引入真实外部服务的前提下，把演示、协作、操作日志和生产准备检查做成项目内可验证闭环。

家庭设置页：

- 家庭设置页继续承担家庭空间列表和成员列表职责，但视觉上应保持轻量工具页，不做后台管理式大表格首页。
- 当前用户是 `OWNER` 时，可以邀请已注册用户、调整成员角色和移除成员；普通成员只展示只读提示和成员信息。
- 邀请成员入口使用弹窗表单，输入账号或邮箱并选择 `OWNER` / `MEMBER`，避免在页面中暴露复杂权限说明。
- 角色调整和移除成员必须有明确操作反馈；移除成员属于破坏性动作，应使用确认弹窗。
- 最近协作日志展示在家庭设置页下方，用于说明家庭邀请、角色调整、移除等关键操作可追踪。

AI 草稿跳转：

- 票据解析结果进入新增设备页时，只预填设备名称、购买日期、购买渠道、价格和建议分类。
- `categoryName` 只在新增设备页应用，编辑设备页不能被 URL 草稿参数覆盖。
- AI 结果必须保持“草稿”定位，用户仍需确认并提交，不允许自动创建设备。

演示与生产门禁：

- smoke 检查覆盖公开首页、登录注册、总览、设备、凭证盒、家庭设置和 AI 辅助入口，作为 UI 静态契约。
- CI 使用 `dist-ci` 目录构建前端，避免本地旧 `dist` 文件锁影响验证。
- 当前 UI 不承诺真实邮件/Webhook、OCR 或生产云部署；这些属于后续增强或部署环境配置。

### 16.8 P24 数据导出体验规则

P24 的导出能力服务于家庭盘点和维修复盘，不把系统扩展成企业资产报表平台。

设备档案页：

- 页面顶部工具区提供“导出设备清单”按钮。
- 导出内容包含当前家庭的设备基础信息、分类、状态、购买信息、位置和备注。
- 没有家庭上下文时按钮不可触发请求。

维修记录页：

- 页面顶部工具区提供“导出费用报表”按钮。
- 导出复用当前日期筛选能力；第一版只导出有实际维修费用且未取消的记录。
- 导出过程提供加载态，下载失败沿用全局请求错误提示。

交互边界：

- 导出文件为 CSV，适合 Excel、Numbers 或表格工具打开。
- 第一版不做异步导出中心、不做导出历史、不做复杂图表报表。
- CSV 字段由后端统一生成，前端不在浏览器中拼接业务数据，避免绕过权限和口径。

### 16.9 P27.1 移动端主导航规则

登录后的手机端必须使用移动应用的信息架构，不能把桌面侧栏改成占满首屏的纵向长条菜单。

- `840px` 以下隐藏桌面侧栏，页面首屏直接展示当前业务内容。
- 顶部栏只保留当前页面标题、家庭切换和用户入口，不重复展示品牌、家庭卡片和完整功能列表。
- 首页、设备、日历、凭证、我的作为 5 个一级入口固定在底部标签栏；图标和文字同时展示。
- 家庭设置属于低频二级入口，放入用户菜单，不占用底部主导航位置。
- 底部标签栏必须预留 `safe-area-inset-bottom`，页面内容增加对应底部留白，不能被固定导航遮挡。
- 每个移动端导航触控区域不小于 44px，选中态除颜色外还要有材质或字重变化。
- 总览页的状态摘要使用两列紧凑网格，禁止把每个统计指标都渲染成整行长卡片。
- 移动端首屏只保留家庭摘要、健康状态和核心指标，卡片内边距与字号应按手机信息密度收敛。
- 手机端不得出现横向滚动；导航、标题和家庭名称在 320px 宽度下仍需可识别。
- 桌面端继续使用左侧导航和顶部工具栏，本次调整不改变既有桌面工作流。

移动端页面职责补充：

- 移动底栏固定为“首页、设备、日历、凭证、我的”，不使用“总览”作为移动端一级入口名称。
- 日历使用独立深链 `/calendar`，不能只通过查询参数滚动到首页中的日历区块。
- 移动首页只展示家庭名称、安心指数和设备/保修/耗材/维修四项核心状态。
- 周任务、房间明细、完整日历、统计图表、最近提醒和最近维修不在移动首页展开。
- 移动日历页只展示月份切换、日期网格和当天提醒，不重复首页摘要与统计指标。
- “我的”进入家庭与成员设置；AI 辅助属于二级能力，不占用移动底栏一级位置。
- 保修、耗材和维修属于设备生命周期二级页，进入后顶部必须显示当前业务标题，底栏保持“设备”选中。
- 提醒中心属于日历二级页，进入后顶部显示“提醒中心”，底栏保持“日历”选中。
- 新增、编辑和详情等深层页面使用具体页面标题，不能回退显示“首页”或“家庭总览”。

移动端列表与系统外观补充：

- 项目当前只提供浅色主题，必须声明 `color-scheme: only light`，避免手机浏览器强制暗色化后破坏玻璃层级与文字对比。
- 成员、协作日志、维修、耗材、保修和提醒在手机端不得继续展示桌面宽表格，统一切换为信息卡列表。
- 移动信息卡按“标题与状态、关键字段、操作区”组织；字段使用两列网格，长文本允许换行，不使用固定列宽。
- 卡片操作区可换行，每个按钮触控高度不小于 44px；危险操作和普通操作保留明显语义区分。
- 手机端筛选表单改为单列，选择器、日期控件和输入框占满可用宽度。
- 手机端弹窗宽度使用视口减安全边距，内容区允许纵向滚动，不得保留 `520px`、`680px` 等桌面固定宽度。
- 分页在手机端只保留前后翻页和必要状态，不展示拥挤的页码、每页条数与总数控件。

### 16.10 P27.2 PWA 交互规则

- 安装入口属于明确命令，只在浏览器触发可安装事件且当前未以独立应用运行时展示。
- 登录后安装入口放入用户菜单，不增加底部第六个标签，也不遮挡当前业务内容。
- 离线状态使用顶部轻量状态条表达，正文只说明当前网络不可用和恢复后的操作，不展示过期业务数据。
- 新版本可用时在用户菜单提供“更新应用”，由用户主动确认后刷新。
- 已经以 `standalone` 模式运行时不再展示安装入口。
- 安装、离线和更新状态必须保留键盘焦点、44px 触控区域及清晰文字，不使用只有颜色含义的提示。
