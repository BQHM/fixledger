# ADR-0004: UI 以家庭场景优先，避免泛后台管理平台表达

- Status: Accepted
- Date: 2026-05-14
- Related: `../ui.md`, `../requirements.md`, `../../frontend/`

## Context

FixLedger 如果只按设备、保修、耗材、维修、附件等模块堆菜单，很容易看起来像普通后台管理平台。用户明确希望项目更有生活工具感，并能在面试中体现产品思考。

核心问题不是把字段改成中文，而是要改变信息组织方式：用户进入系统后应该先看到家庭状态、近期事项、日历提醒和设备生命周期，而不是数据库模块列表。

## Decision

前端产品表达采用家庭场景优先：

- 一级导航使用“我的家、家庭日历、设备护照、凭证盒、智能助手、我的家庭”。
- 首页优先展示家庭健康分、本周设备事项、真实图钉风格提醒日历和房间设备概览。
- 设备详情表达为“设备护照”和生命周期时间线。
- 附件表达为“凭证盒”，突出发票、保修卡、说明书、维修单的收纳感。
- AI 表达为“智能助手”，定位为辅助录入和辅助总结，不做产品主角。

## Consequences

### Positive

- 项目更容易和普通资产管理系统区分开。
- 面试时能讲清“业务场景驱动 UI，而不是数据库表驱动 UI”。
- 后续移动端、小程序或二维码标签也能沿用家庭场景表达。

### Trade-offs

- Element Plus 表格和表单仍可能带来后台感，需要继续通过卡片、日历、时间线和生活化文案弱化。
- 一些高级管理能力仍需要表格视图，但不应作为第一印象入口。
- UI 体验升级需要持续和真实接口、数据结构同步，不能只做静态视觉稿。

## Verification

- `docs/ui.md` 已记录 P8 后的信息架构和面试演示路径。
- 前端导航已调整为家庭场景入口。
- 后续 P9.6 / P15 继续深化设备护照、凭证盒和家庭日历。
